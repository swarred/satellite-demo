The challenge

Disrupted links are not the exception — they are the environment

Satellites operate in an environment where connectivity to the ground is intermittent by nature and contested by adversaries. The question is not whether a disruption will occur, but whether the mission continues when it does.

Without software-defined resilience

  • × Operators must manually detect and respond to link loss
  • × Anomaly detection halts during blackout windows
  • × Data collected during DDIL is lost or unclassified
  • × Recovery depends on manual reconfiguration after reconnect

With Red Hat’s software-defined approach

  • ✓ Link disruption triggers automated response in seconds
  • ✓ Satellite autonomously classifies anomalies with local AI
  • ✓ All offline classifications queued and flushed on reconnect
  • ✓ Zero operator action required throughout the event

The key insight: resilience is not built into the application layer — it is built into the operating system itself. The satellite’s OS adapts to its connectivity state, switching between mission profiles as conditions change.

What you’ll see

The demo in three acts

This is a live, end-to-end demonstration. Every step is running on real software — no slides, no pre-recorded video, no scripted output.

Act 1 — Normal operations

Link active. Ground in control.

The satellite is in orbit, continuously collecting sensor data. The secure link to the ground station is active through Red Hat Service Interconnect.

  • Satellite telemetry streams to the ground station in real time
  • AI on OpenShift classifies space anomalies as they arrive
  • Mission operators see live situational awareness
  • Event-Driven Ansible watches the link health, ready to act
Act 2 — DDIL event

Link disrupted. Autonomous mode engages.

A link disruption is triggered. Event-Driven Ansible detects the loss within seconds. No operator action is taken — the satellite responds on its own.

  • EDA rulebook detects ground station is unreachable
  • RHEL Image Mode switches the satellite OS to its autonomous mission image
  • A local AI model — embedded in the OS image — begins classifying anomalies
  • All classifications are queued locally. The satellite never stops operating.
Act 3 — Reconnect

Link restored. Full picture recovered.

The link is restored. EDA detects it automatically. The satellite transitions back and the ground station regains complete situational awareness.

  • EDA detects ground station is reachable again
  • RHEL Image Mode transitions back to the connected mission image
  • The offline classification queue flushes automatically to the ground station
  • Operators see a complete, uninterrupted picture — including what was classified offline

What makes this different: conventional edge resilience keeps the application running. This demonstration shows the operating system itself adapting — switching to a purpose-built autonomous image with an embedded AI model, then switching back — with no configuration drift, no manual steps, and no data loss.

Red Hat products at work

The technology behind the demo

Four Red Hat products, each doing a distinct job, composing into a mission-resilient architecture.

RHEL Image Mode

The satellite’s adaptable operating system

RHEL Image Mode treats the operating system as a container image — built once, cryptographically verified, and deployed atomically. The satellite carries two mission images: one for connected operations, one for autonomous DDIL operations. Switching between them takes seconds and requires no manual reconfiguration. Configuration drift is architecturally impossible.

For compliance officers: every deployed state is a known, immutable artifact — directly supportable in RMF/STIG workflows and ATO documentation.

Red Hat OpenShift

The ground station platform

The ground station runs as containerized workloads on OpenShift, providing a real-time mission operations interface and centralized observability across the satellite fleet. OpenShift provides the scalable, Kubernetes-native foundation for running AI inference, data ingestion, and operator dashboards in a consistent, auditable environment.

Connects naturally to Zero Trust Architecture mandates — workload isolation, role-based access, and software supply chain integrity are first-class platform features.

Event-Driven Ansible

The autonomous decision engine

Event-Driven Ansible continuously monitors the link state between the satellite and the ground station. When conditions change, it fires the appropriate playbook automatically — triggering the OS image switch, initiating reboot, and managing the reconnect sequence. There is no human in this loop. The response time from disruption to autonomous operation is measured in seconds.

Reduces operator burden at exactly the moment it is highest: during a link disruption in a contested environment.

Red Hat Service Interconnect

The secure cross-domain link

Red Hat Service Interconnect establishes an application-layer, mutually authenticated overlay network between the satellite and the ground station. It works across network boundaries without requiring changes to firewalls or routing infrastructure. Services on the satellite appear as local services on the ground station through a cryptographically secure tunnel.

Designed for exactly the kind of asymmetric, cross-domain connectivity that characterizes space-to-ground links.
